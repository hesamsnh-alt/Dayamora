# دایامورا — نسخه ۲.۰

فروشگاه محلی همراه دیتابیس SQLite، پنل مدیریت، باشگاه مشتریان، صفحه محصول و خرید با بودجه.

## اجرای سریع در ویندوز و VS Code

۱. اگر نسخه قدیمی روشن است، در ترمینال آن Ctrl+C بزنید.
۲. این ZIP را در یک پوشه جدید در F استخراج کنید؛ نسخه قبلی را برای احتیاط نگه دارید.
۳. پوشه Dayamora داخل بسته را با File → Open Folder در VS Code باز کنید.
۴. در ترمینال همان پوشه بنویسید:

```powershell
npm run dev
```

نیازی به npm install نیست؛ موتور SQLite همراه بسته است.
حداقل Node.js مورد نیاز 18.17 است. اگر نسخه قبلی با npm run dev اجرا می‌شد، همان Node را می‌توانید استفاده کنید.

۵. اولین بار این آدرس را باز کنید:

http://localhost:3000/setup

ایمیل مدیر از قبل تعیین شده است: hesamsnh@gmail.com
نام نمایشی و رمز خودتان را تعیین کنید. رمز پیش‌فرضی وجود ندارد و در چت وارد نمی‌شود.
حداقل طول رمز ۱۰ کاراکتر است. رمز را نگه دارید؛ بازیابی رمز با ایمیل هنوز فعال نیست.
پس از ساخت، این صفحه دیگر اجازه ساخت مدیر جدید نمی‌دهد.

## آدرس‌ها

- فروشگاه: http://localhost:3000
- مدیریت: http://localhost:3000/admin
- باشگاه و حساب مشتری: http://localhost:3000/club
- خرید با بودجه: http://localhost:3000/budget
- جزئیات محصول: روی عکس محصول کلیک کنید؛ مثلاً http://localhost:3000/product?id=3

این آدرس‌ها روی کامپیوتر خودتان کار می‌کنند. این نسخه به سایت اینترنتی قبلی وصل نیست و روی همان لینک قدیمی منتشر نشده است.

## مدیریت محصول

با حساب مدیر وارد شوید. در تب محصولات «محصول جدید +» را بزنید.
نام، برند، دسته، قیمت به تومان، موجودی کل، مدل‌ها/سایزها، توضیحات و عکس اصلی را وارد کنید.
می‌توانید حداکثر ۸ عکس تکمیلی برای گالری بارگذاری کنید؛ هر عکس تا ۴ مگابایت، JPG، PNG یا WebP.
موجودی فعلاً در سطح محصول است؛ بین تمام مدل‌ها و سایزها مشترک است.
قیمت قبل از تخفیف اختیاری است. فقط اگر واقعاً تخفیفی وجود دارد وارد کنید؛ باید از قیمت فروش بیشتر باشد.
برای حذف از نمایش، محصول را ویرایش و «نمایش در فروشگاه» را غیرفعال کنید. سابقه سفارش حفظ می‌شود.
شش محصول اول نمونه هستند. مشخصاتشان را پیش از فروش واقعی بررسی و تکمیل کنید.

## ذخیره انتخاب مشتری

مشتری ثبت‌نام می‌کند و با ایمیل و رمز وارد می‌شود.
سبد، علاقه‌مندی‌ها و حداقل/حداکثر بودجه در دیتابیس به حساب خودش متصل‌اند.
انتخاب مهمان تا قبل از ورود، فقط در مرورگر ذخیره می‌شود؛ هنگام ورود قابل انتقال به حساب است.
کمد شخصی: مشتری عکس لباس و آیتم خودش را اضافه می‌کند. عکس‌ها فقط با حساب مالک همان آیتم قابل دریافت‌اند.
استایل شخصی: مشتری از محصولات فروشگاه و آیتم‌های کمد، ترکیب می‌سازد و ذخیره/ویرایش می‌کند.
این استایل‌ساز دستی است؛ تولید استایل یا تشخیص عکس با هوش مصنوعی ندارد.

## بودجه

صفحه مستقل خرید با بودجه از دکمه صفحه اصلی باز می‌شود.
حداقل و حداکثر قیمت، اسلایدر سقف قیمت، دسته‌بندی، جستجو و مرتب‌سازی دارد.
بودجه قیمت هر محصول است؛ مجموع سبد جداگانه محاسبه می‌شود.
«پیشنهاد ویژه» فقط کالاهایی را نمایش می‌دهد که مدیر برایشان قیمت قبل از تخفیف تعیین کرده باشد.
«پرطرفدار» فقط براساس تعداد محصولات در سفارش‌های تکمیل‌شده کار می‌کند؛ تا قبل از وجود داده، خالی است.
ذخیره بودجه برای عضو در حساب و برای مهمان در مرورگر انجام می‌شود.

## باشگاه، سفارش و امتیاز

مشتری در پروفایل، شماره تماس و آدرس را تکمیل می‌کند و از سبد «ثبت درخواست سفارش» می‌زند.
این ثبت، پرداخت بانکی نیست. وضعیت اولیه «در انتظار بررسی» است.
مدیر از تب سفارش‌ها آن را تأیید، تکمیل یا لغو می‌کند.
تأیید، موجودی را کم می‌کند. لغو سفارش تأییدشده، موجودی را برمی‌گرداند.
مدیر هنگام تکمیل، امتیاز سفارش را تعیین می‌کند. یک سفارش دوبار امتیاز نمی‌گیرد.
همچنین از تب باشگاه، تغییر دستی امتیاز با ثبت دلیل ممکن است؛ مانده منفی مجاز نیست.
امتیازها فعلاً نشان همراهی‌اند؛ اعتبار نقدی و تبدیل خودکار به تخفیف نیستند.
مدیر می‌تواند اطلاعات تماس، سبد، علاقه‌مندی‌ها، بودجه و امتیازهای اعضا را ببیند.
عکس‌های کمد شخصی برای مدیر یا مشتری دیگر از مسیر عمومی باز نمی‌شوند.

## نظرات و امتیاز محصول

در صفحه محصول، تب نظرات و امتیاز ۱ تا ۵ ستاره وجود دارد.
ثبت نظر فقط برای حسابی مجاز است که همان محصول را در سفارش تکمیل‌شده دارد.
برای هر مشتری و محصول یک نظر ثبت می‌شود؛ ثبت دوباره، همان نظر را به‌روز می‌کند.
میانگین و تعداد فقط از نظرهای منتشرشده محاسبه می‌شوند. نظر یا امتیاز ساختگی وارد نشده است.
مدیر در تب «نظرات و امتیازها» می‌تواند نظر را مخفی یا دوباره منتشر کند؛ متن مشتری را تغییر نمی‌دهد.
سفارش تکمیل‌شده در این نسخه به معنای تأیید بانکی پرداخت نیست.

## فایل دیتابیس و پشتیبان

در اولین اجرا خودکار ساخته می‌شود:

```text
data/dayamora.sqlite
```

عکس محصولات داخل data/uploads و عکس کمد داخل data/wardrobeuploads ذخیره می‌شوند.
تمام اطلاعات عملیاتی داخل پوشه data است. این پوشه را حذف یا با پوشه خالی جایگزین نکنید.
برای پشتیبان: سرور را با Ctrl+C متوقف کنید، سپس از کل پوشه data یک کپی بگیرید.
برای بازیابی: وقتی سرور خاموش است، پوشه data نسخه پشتیبان را در همان محل قرار دهید.
فایل server.lock را به‌عنوان دیتابیس تلقی نکنید؛ فقط برای جلوگیری از اجرای هم‌زمان دو سرور است.
اگر فرایند ناگهان بسته شد و خطای قفل باقی ماند، ابتدا مطمئن شوید سرور قبلی روشن نیست؛ سپس فقط data/server.lock را حذف کنید.

## محدوده این نسخه

این بسته برای اجرای محلی و بررسی جریان‌های فروشگاه ساخته شده است؛ در حالت معمول فقط روی localhost گوش می‌دهد.
پرداخت آنلاین، تأیید ایمیل، ارسال ایمیل/پیامک و بازیابی رمز با ایمیل متصل نیستند.
برای مشتریان واقعی اینترنتی، به استقرار سرور، HTTPS، سرویس ایمیل، پشتیبان‌گیری و اتصال پرداخت نیاز است؛ کپی فایل‌های public روی هاست استاتیک این دیتابیس را فعال نمی‌کند.
SQLite این پروژه برای یک فرایند سرور و حجم کم طراحی شده است؛ فایل دیتابیس بین چند نمونه سرور به اشتراک گذاشته نمی‌شود.
تصاویر نمونه از طرح‌های مرجع استخراج شده‌اند و جای عکس اصلی محصولات را نمی‌گیرند.

## بررسی فنی

```powershell
npm test
```

تست از دیتابیس موقت استفاده می‌کند و به data واقعی شما دست نمی‌زند.
موارد پوشش‌داده‌شده: ماندگاری بعد از ری‌استارت، جداسازی دو مشتری، جلوگیری از دسترسی غیرمدیر، ثبت محصول و عکس، بودجه، سفارش، موجودی، امتیاز غیرتکراری، نظر مشتری و مدیریت انتشار، کمد و استایل خصوصی.
صفحه بودجه، صفحه محصول، انتقال به سبد و صفحه شروع مدیر نیز در مرورگر بررسی شده‌اند.

## ساختار

- server.cjs: سرور محلی، ورود، مجوزها و API
- public/: صفحات، استایل‌ها، تصاویر و کد سمت مرورگر
- vendor/: sql.js نسخه 1.15.1 با مجوز MIT برای اجرای بدون نصب
- tests/: تست جریان‌ها با دیتابیس موقت
- data/: اطلاعات شما؛ خودکار در اولین اجرا ساخته می‌شود و داخل ZIP نیست
