پچ دایامورا — بر اساس فایل dayamora4.zip

نصب:
۱. از پوشه فعلی پروژه یک کپی پشتیبان بگیر.
۲. فایل‌های این ZIP را داخل ریشه همان پروژه که package.json دارد کپی و جایگزین کن. پوشه‌های lib و public و netlify باید با پوشه‌های موجود ادغام شوند.
۳. در ترمینال VS Code داخل پوشه پروژه اجرا کن:
npm ci
npm test
npm run build
۴. برای ثبت در گیت:
git add .
git commit -m "Restore magazine and customer tools; complete product import review"
git push origin main
۵. نسخه جدید را روی Netlify دیپلوی کن. این پچ خودش چیزی را پوش یا دیپلوی نکرده است. دیتابیس را دوباره راه‌اندازی نکن و npm run db:init اجرا نکن.

مجله:
مسیر سایت آنلاین /api/journal هنگام بررسی ۴۰۴ JSON برمی‌گرداند، در حالی که فایل‌های صفحات موجودند. یک مقاله منتشرشده در دیتابیس DAYAMORA پیدا شد؛ محتوا حذف نشده است.
پس از دیپلوی جدید، «مجله دایامورا» در صفحه اصلی به /discover/journal می‌رود. مدیریت آن از «مدیریت مجله» در پنل و /journal-admin.html در دسترس است. مقاله جدید، عکس، متن، پیش‌نمایش، انتشار و بایگانی همان ابزار موجود هستند و حفظ شده‌اند.
فایل‌های مجله و مسیرهای Netlify موجود داخل پچ آمده‌اند تا زنجیره کامل حفظ شود. مطلب آزمایشی یا محتوای جدید در دیتابیس نساخته‌ایم.

مشتریان:
پنل مدیریت ← باشگاه مشتریان ← «ساخت حساب مشتری +». نام اختیاری و ایمیل مشتری را وارد کن؛ لینک خصوصی تعیین رمز نمایش داده می‌شود. کنار هر مشتری هم «لینک بازیابی رمز» وجود دارد.
لینک یک‌بارمصرف است و ۳۰ دقیقه اعتبار دارد. فقط برای همان صاحب حساب، پس از احراز هویت، خصوصی ارسال شود. مدیر رمز قبلی را نمی‌بیند.
ثبت‌نام با ایمیل شروع می‌شود و سپس نام، تلفن، رمز دلخواه فروشگاه و تکرار آن را می‌پرسد. رمز صندوق ایمیل خواسته نمی‌شود.
ارسال خودکار ایمیل نیازمند تنظیم RESEND_API_KEY و DAYAMORA_MAIL_FROM با دامنه تأییدشده در Netlify است. DAYAMORA_SITE_URL باید آدرس سایت باشد. این متغیرها با این پچ تنظیم نشده‌اند. لینک دستی مدیر بدون سرویس ایمیل هم قابل استفاده است. فراموشی رمز عمومی بدون تنظیم ایمیل، خطای روشن نشان می‌دهد و به‌اشتباه ادعای ارسال نمی‌کند.

ورود محصول از لینک:
پنل مدیریت ← محصولات ← ورود محصول از لینک.
عنوان، برند، توضیح، عکس‌ها و رنگ/سایزهای قابل استخراج از داده‌های عمومی صفحه پیشنهاد می‌شوند. عکس دلخواه را با دکمه دریافت عکس انتخاب کن یا از دستگاه اضافه کن. برش عکس با درصد و پیش‌نمایش قابل تنظیم است؛ خروجی WebP تا ضلع بزرگ ۱۸۰۰ پیکسل است و تصویر کوچک بزرگ‌نمایی نمی‌شود.
این برش حذف پس‌زمینه، جداکردن لباس از شخص یا پرو مجازی نیست. ترجمه یا تولید متن با مدل پولی هم استفاده نمی‌شود؛ توضیح پیشنهادی از اطلاعات واقعی منبع تهیه می‌شود و باید ویرایش/بررسی شود. اطلاعاتی که منبع منتشر نکرده ساخته نمی‌شود.
«ذخیره پیش‌نویس و بررسی نهایی» عکس‌ها را در فضای آپلود موجود فروشگاه و پیش‌نویس را در جدول موجود product_imports ذخیره می‌کند. از «پیش‌نویس‌های لینک» می‌توان دوباره آن را باز کرد. تغییرات فرم نهایی تا کلیک تأیید، ذخیره نشده‌اند.
در فرم نهایی قیمت تومان، موجودی هر رنگ/سایز، هزینه ارسال و عکس‌ها را بررسی کن. نمونه‌رنگ پیش‌فرض خاکستری است؛ کد رنگ واقعی را خودت تنظیم کن. موجودی از منبع کپی یا حدس زده نمی‌شود. گزینه نمایش در فروشگاه پیش‌فرض خاموش است؛ برای انتشار عمومی آن را روشن و «تأیید و ذخیره محصول» را بزن. ارسال تکراری تأیید همان محصول را برمی‌گرداند.
خرید از Temu/Amazon، اتصال حساب فروشنده یا همگام‌سازی قیمت و موجودی انجام نمی‌شود. بعضی فروشگاه‌ها دریافت خودکار را محدود می‌کنند یا مشخصات را فقط پس از اجرای جاوااسکریپت نشان می‌دهند؛ در این موارد فرم دستی ارائه می‌شود. استخراج کامل از همه سایت‌ها تضمین نشده است.

محدوده و بررسی:
ساختار، جدول یا اطلاعات دیتابیس تغییر نکرده است. فقط ساختار جدول و تعداد مقاله‌ها در DAYAMORA خوانده شد. سایر پروژه‌ها دست‌نخورده‌اند.
تست‌های خودکار: ۵۵ موفق، یک تست وابسته به تنظیمات محیط اجرا نشده. build و تست‌های اتصال مجله، ابزار مشتری، استخراج اطلاعات، محدودیت دریافت شبکه، پیش‌نویس و جلوگیری از تأیید تکراری بررسی شدند.
رابط مشتری و انتقال پیش‌نویس به فرم نهایی با داده ساختگی در مرورگر بررسی شد؛ ذخیره واقعی محصول یا مشتری روی دیتابیس زنده آزمایش نشده است. صفحات/ظاهر/جدول سایز محصولات بازطراحی نشده‌اند.
این پچ به ساختار فعلی جدول dayamora.product_imports در دیتابیس DAYAMORA وابسته است: وضعیت‌های draft/review/published و ستون product_id، بدون نیاز به مهاجرت جدید.
